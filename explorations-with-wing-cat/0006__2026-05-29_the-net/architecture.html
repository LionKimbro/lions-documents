Architecture

From stream to staging to archive

The architecture should be file-first and boring in the best way: folders for intake, JSON files for staging, JSONL for the archive, and assets stored by stable IDs.

Each capture source gets normalized into the same remembered thing format before it reaches the tagger window.

Capture sources

Downloads

New files copied or moved into assets, then represented by staging records.

Bookmarks

Chrome bookmark drop files become URL records with title, URL, and timestamp.

Pasted

Manual URLs, quotes, snippets, and notes can enter the same staging lane.

Screenshots

Screenshots behave like images but can later gain OCR, source URL, or context.

Rolling context

Recently captured page as source clue

Heuristic

When a page is captured, Catchbasket writes a small state/recent_context.json file. If an image is downloaded shortly afterward, the download scanner can suggest that recent page as the image's framing context.

The system should show this as a suggestion for Lion to accept or reject, not as a silent fact.

Archive operation

Append, then move aside

The basic archive operation should be append-only. For each selected staged record, write one JSON object as one line in remembered-stuff.jsonl, then move the staging file into processed/.

This keeps the archive grep-friendly, repairable, and compatible with later tools that may build indexes or views.
