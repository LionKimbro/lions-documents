Provenance

The browsing moment matters

Downloaded images need more than a filename. They need the URL of the image when known, the page that framed the image, and sometimes the nearby captures that explain why the image mattered.

This turns Catchbasket from a pile of objects into a map of encounters.

URL distinctions

SOURCE_URL

The direct artifact URL, such as the raw image file address. Useful, but often context-poor.

FRAMING_URL

The page where the artifact was seen. This often carries the meaning, caption, author, and surrounding argument.

REFERRER_URL

The browser's reported source of a download, when available from a future extension or browser integration.

Near-term heuristic

Recently captured page plus new download

Rule

If Lion captures a page and downloads an image within the next few minutes, suggest that the image belongs with that page.

UI wording

This image may belong with "Green caterpillar identification," captured 42 seconds before the download.

Actions

Accept Link, Reject, Open Page, Open Image. The suggestion stays visible and editable.

Relationship model

Parent links and capture groups

A strict parent-child link is useful when a downloaded image clearly came from a captured page. The child record should point to the parent with PARENT_GUID; children can be computed later by scanning records.

A CAPTURE_GROUP is looser and often more honest. It can bind a page, three images, a PDF, and a note into one encounter without insisting that the page is the parent of everything.

Later extension

Chrome capture plugin

A future Chrome extension can do the clean version: capture this page, capture this image, capture both, or capture image plus selected text and the current tag brush.

That extension could send page URL, page title, image URL, alt text, selected text, and timestamp directly into the same staging format. The humble timing heuristic still makes sense first because it gets much of the value with little machinery.
